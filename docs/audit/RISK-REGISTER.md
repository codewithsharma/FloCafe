# Risk Register — OPERAVIA (FloCafe)

**Date:** 2026-08-21 · **Version:** 3.0.5 · **Schema:** `user_version = 86`

Structured, evidence-backed risk table aggregated from the lens audits. Each risk cites the source finding. **Severity** is the intrinsic seriousness; **Probability** is the likelihood of the adverse event given the current code and the product's target deployment (single-store, local-first, owner-operated, optionally LAN); **Impact** is the consequence if it occurs. Owners are role-based (the repo has `CODEOWNERS`; map to real names on adoption).

> Context that bounds several probabilities: this is an **offline-first single-store desktop POS**, not a multi-tenant cloud service. Risks that would be severe at web scale (e.g. synchronous SQLite, LAN exposure) are scored for the actual deployment. No live penetration test, load test, or fuzzing was performed — dynamic-behavior risks are reasoned from code and labelled accordingly.

## 3. Top 5 risks (for the executive summary)

1. **R-02** — Orphaned test suites (recovery + boundary guards not in CI): the safety nets exist but don't run.
2. **R-01** — Incomplete money-cents cutover: float accumulation on core totals in a financial system.
3. **R-03** — Untested frontend: the cashier UI, which _is_ the product, has no focused automated coverage.
4. **R-08 / R-09** — Distribution signing: Windows unsigned; signed macOS blocked on credentials.
5. **R-04 / R-05** — Untested concurrency and single-platform CI for a multi-process, tri-platform app.
