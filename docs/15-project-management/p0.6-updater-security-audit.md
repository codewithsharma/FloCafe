## 1. Current updater architecture (post-B2)

```
GitHub Releases (FreeOpenSourcePOS/FloCafe)
  └─ electron-builder publish → latest.yml / latest-mac.yml + artifacts + blockmaps
       │
       ▼
Main process (electron-updater)
  setupAutoUpdater(): autoDownload=true, autoInstallOnAppQuit=false
  Startup: non-store → check after 5s
  Menu Help → Check for Updates → checkForUpdates() (main-only, no IPC)
       │
       ├─ download → update-downloaded → updateDownloaded=true
       │              └─ webContents.send('update-status', ready-to-install)
       │
       └─ IPC (renderer via preload)
            get-update-status / get-status / check-for-updates  → PUBLIC
            restart-and-install(token) → authorizeOwnerManagerJwt → audit → quitAndInstall
                 │
                 ▼
            UpdateBadge "Restart Now" → localStorage token → restartAndInstall(token)
```

| Component | Location | Role |
|-----------|----------|------|
| IPC JWT helper | `main/security/ipc-auth.ts` | `authorizeOwnerManagerJwt` — signature, revoke, stale, active, role |
| Restart gate | `main/security/restart-and-install.ts` | Auth + download flag + audit + quitAndInstall |
| IPC registration | `main/index.ts` | Passes token into `handleRestartAndInstall` |
| Preload | `main/preload.ts` | `restartAndInstall(token)` |
| UI | `useUpdateStatus.ts` | Passes `localStorage.getItem('token')` |

## 2. `restart-and-install` threat model (closed)

| Before B2 | After B2 |
|-----------|----------|
| Any renderer JS could call `restartAndInstall()` | Requires valid owner/manager JWT |
| Only gate: `updateDownloaded` | Auth first, then `updateDownloaded` |
| No audit | `updater.restart_and_install` audit on success/failure |
| XSS → forced quit/install for any role | XSS without owner/manager JWT cannot install |

**Still accepted residual:** stolen active owner/manager `localStorage` JWT can authorize restart (same as HTTP API compromise). CSP / httpOnly JWT → Phase C.

**Supply chain unchanged:** handler still cannot pass arbitrary artifacts; electron-updater + platform signing verify packages.

## 4. Authorization decision (accepted)

**Option B — authenticated owner/manager JWT.**

- Least privilege for an availability/ops control
- Master PIN reserved for irreversible data plane (backup/restore)
- Reuses `getJWTSecret`, `isTokenRevoked`, `isTokenStale`, `getUserAuthStatus` — no second auth system

## 5. Audit logging (implemented)

| Field | Value |
|-------|--------|
| `action` | `updater.restart_and_install` |
| `entityType` | `app` |
| `entityId` | target version when known, else `app` |
| `actorUserId` | verified JWT subject (null on auth failure) |
| `metadata` | `{ role?, updateDownloaded, fromVersion, toVersion }` — **never** token/secret/PIN |

Failures also audited with `result: 'failure'` and `reason` (`unauthorized` / `forbidden` / `update_not_ready`).
