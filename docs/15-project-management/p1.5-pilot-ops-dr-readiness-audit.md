## 3. Exact mandatory pilot conditions

Grounded in existing audits (especially P0.6 §11) + this discovery — **not invented product features**:

1. **OPS-01:** Prefer `network_mode=localhost`. If multi-device (`kds_lan` / `lan`), **staff-only SSID/VLAN only — never guest Wi‑Fi**. Cleartext LAN accepted only under that ops rule.
2. **Master PIN** set at install; known only to owner (and at most one manager); **written escrow** held offline by owner.
3. **One practiced backup → destroy simulation → restore drill** completed and recorded (see §8) before first live service day.
4. **REC-01 stop-rule trained:** unexpected first-time setup → STOP → do not initialize → recover/restore.
5. **Packaged builds only**; **Windows pilots require signed artifacts** (WIN-01).
6. **Linux pilots:** desktop keyring available so `safeStorage` works (not silent `basic_text` degradation).
7. **Backup discipline:** local backups treated as **sensitive business/PII data**; Drive optional but if used, owner understands schedule/retention and that Drive `backup-now` is owner-JWT gated (DRV-01 residual).
8. **DB backup alone ≠ full DR:** same-machine keep `jwt-secret.enc`; new-machine needs Master PIN + JWT recover path.
9. **Owner/manager account hygiene**; rotate JWT secret via Master PIN if compromise suspected.
10. **Do not open pilot** until a **concise pilot ops pack** (P1.5) exists covering install → daily close → backup verify → DR → incident reporting.

## 8. Designed controlled DR drill (not executed)

**Purpose:** Prove café can recover money state under REC-01 without silent FIRST_INSTALL.  
**Environment:** Non-production / pilot training machine with packaged build.  
**Owner present:** Master PIN holder.

### Steps

1. **Seed known café data:** products, one open shift, 2–3 orders, at least one **partial payment**, one **refund**, day-close if in scope for the day.
2. **Record baseline:** bill totals, gross tender, refunds, outstanding (FIN-01), shift expected cash, day-close Cash In / Refunds / Net if closed, last audit events, app version, `network_mode`, printer/KDS status.
3. **Create local backup** (Master PIN); note path, size, timestamp. Optional: confirm Drive copy if enabled.
4. **Stop application** cleanly.
5. **Simulate DB loss:** move/rename `flo.db` (+ wal/shm if present); **keep** `install-state.json` and `jwt-secret.enc` for same-machine path.
6. **Start app → confirm RECOVERY_REQUIRED** (not setup). Confirm money APIs unavailable; KDS/Server App/mDNS not started.
7. **Restore** via recovery UI / Database Tools with Master PIN.
8. **Verify financial state** against baseline (orders, bills, payments, partials, refunds, FIN-01 outstanding, shifts, day-close, audits).
9. **Verify JWT state:** same-machine → login works with existing secret; if simulating new-machine, remove `.enc` and confirm `recovery_required` (do not complete silent setup).
10. **Verify network/KDS/printer:** mode still correct; KDS reconnects on staff LAN only; printer smoke print if available.
11. **Controlled test sale:** one order → pay → confirm.
12. **Record RTO** (stop → restored usable POS) and **RPO** (time since last backup / data loss window). Pass criteria: RTO ≤ 30 minutes target for pilot; RPO = last successful backup; zero silent FIRST_INSTALL; FIN-01 invariant holds.

### Pass / fail

| Pass | Fail |
|------|------|
| Recovery UI, not setup | Setup wizard accepted / owner created |
| Financial baselines match | Missing payments/refunds/shift |
| Post-restore test sale OK | Money APIs during recovery |
| RTO/RPO recorded | No backup / wrong backup restored without detection |

## 11. Proposed pilot operations checklist

### Before first live day

- [ ] Packaged build installed (Windows: **signed**)
- [ ] Owner created; Master PIN set; escrow recorded offline
- [ ] Linux: keyring confirmed working (`safeStorage`)
- [ ] Local backup created and path known; treated as sensitive
- [ ] Drive backup configured **or** explicitly deferred with local-only policy
- [ ] `network_mode` chosen; if not localhost → staff SSID only; guest Wi‑Fi verified unreachable
- [ ] KDS paired on staff LAN (if used); mDNS/QR understood for mode
- [ ] Printer smoke test
- [ ] REC-01 stop-rule briefed to owner/manager
- [ ] Controlled DR drill (§8) **passed** and RTO/RPO recorded
- [ ] Post-restore financial checklist completed once
- [ ] Incident reporting path known (who to call / GitHub / support)

### Daily

- [ ] Open shift / float as required
- [ ] End of day: close shift / day-close per café policy
- [ ] Create or confirm daily backup (local minimum)
- [ ] Spot-check backup file exists and is non-trivial size

### Weekly

- [ ] Restore drill on **staging/spare** if available (or tabletop review)
- [ ] Confirm Drive retention / local backup copies still accessible
- [ ] Review open incidents

### On incident (DB / setup surprise)

- [ ] STOP if unexpected setup appears
- [ ] Do not initialize; do not take payments
- [ ] Enter recovery; restore correct backup
- [ ] Verify financial + login; test sale
- [ ] Report incident with version, OS, logs, RTO
