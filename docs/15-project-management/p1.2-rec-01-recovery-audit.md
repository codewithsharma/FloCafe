## State transition rules

| State | Condition |
|-------|-----------|
| `FIRST_INSTALL` | No marker |
| `ACTIVE` | Marker present + usable DB with users (or after successful setup/restore) |
| `RECOVERY_REQUIRED` | Marker present + missing DB **or** empty operational DB (`users === 0`) |

Transitions:

- FIRST_INSTALL → ACTIVE: successful `/auth/setup/initialize` writes marker  
- ACTIVE → RECOVERY_REQUIRED: marker + missing/empty DB at startup  
- RECOVERY_REQUIRED → ACTIVE: successful restore (existing IPC restore)  
- ACTIVE → FIRST_INSTALL: explicit factory reset (`POST /db-tools/initialize`) clears marker after safety backup  

---

## Startup behavior

1. If `flo.db` missing and marker exists → throw `DatabaseRecoveryRequiredError` (**do not create DB**).  
2. If DB exists → open + migrate as before.  
3. If marker + `users === 0` → set recovery latch (`empty_database`).  
4. If `users > 0` and no marker → **backfill** marker (upgrade path).  
5. Recovery mode (`main/index.ts`): start Express (static + gated API) + IPC restore; **do not** start KDS, Server App, mDNS, cloud money path; load `/recovery`.

---

## Recovery behavior

- UI: `/recovery` — Restore Backup (Master PIN + existing IPC), Support, Exit.  
- `/setup` and money APIs blocked.  
- `/api/health` returns `status: recovery_required`.  
- Corrupt restore fails closed; no empty DB created when live DB was missing.  
- Successful restore → marker ensured → app relaunches into ACTIVE.

---

## Factory-reset behavior

`resetDatabaseWithBackup()` (post-hardening ordering):

1. Safety backup (unchanged — before any destructive work)  
2. Wipe live DB files  
3. Create empty reset DB via `initDatabase({ allowCreateDespiteMarker: true })` and durably commit (`wal_checkpoint` + sync)  
4. **Only then** `clearInstallationMarker()` → FIRST_INSTALL  

Step 3 keeps the marker on disk so a crash mid-reset yields `RECOVERY_REQUIRED`, not silent FIRST_INSTALL. The `allowCreateDespiteMarker` flag is factory-reset-only and does not weaken normal missing-DB recovery.

**Rollback:** if wipe/recreate fails (or test inject after empty init), restore safety backup, reopen DB, and **leave/restore the marker**. Next boot with a missing DB cannot become silent FIRST_INSTALL — marker presence ⇒ `RECOVERY_REQUIRED`.

Master PIN + phrase `INITIALIZE` unchanged. No silent reset.

---

## Backfill strategy

On healthy open: if `COUNT(users) > 0` and marker absent → write marker.  
Never backfill for empty DBs / first install / silent REC-01 empties.

---

## Recovery API middleware (fail closed)

`recoveryApiProtectionMiddleware` in `main/server.ts`:

- While `isRecoveryRequired()`: money/business APIs return **HTTP 503** (`recovery_required: true`). Allowlist: `/api/health`, `/api/auth/setup/status`, `/api/auth/jwt-secret*`.  
- If install-state evaluation **throws**: return **HTTP 503** with `reason: RECOVERY_STATE_UNAVAILABLE` — **do not** call `next()` (no fail-open into money routes).
