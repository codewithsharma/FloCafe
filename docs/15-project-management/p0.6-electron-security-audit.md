## 1. Current Electron architecture

```
┌─────────────────────────────────────────────────────────────────┐
│ Renderer (Next.js static export @ http://localhost:PORT)        │
│ Trust: UNTRUSTED content surface                                │
│ Caps: DOM, fetch to local Express, localStorage JWT,            │
│       window.electronAPI (bridged), navigator.usb (WebUSB)      │
│ No Node, no require, no raw ipcRenderer                         │
└────────────────────────────┬────────────────────────────────────┘
                             │ contextBridge (allowlisted methods)
┌────────────────────────────▼────────────────────────────────────┐
│ Preload (main/preload.ts → dist/preload.js)                     │
│ Trust: PRIVILEGED bridge (Electron preload)                     │
│ Caps: ipcRenderer.invoke/on for fixed channels only             │
│ Leaks to page: process.platform as electronAPI.platform         │
└────────────────────────────┬────────────────────────────────────┘
                             │ IPC (ipcMain.handle)
┌────────────────────────────▼────────────────────────────────────┐
│ Main process (Electron + Express :3001 + optional KDS/Server)   │
│ Trust: FULLY TRUSTED                                            │
│ Caps: SQLite (better-sqlite3), fs, safeStorage, printers        │
│       (child_process/lp), shell.openExternal (allowlisted),     │
│       autoUpdater, Master PIN, JWT secret service               │
└─────────────────────────────────────────────────────────────────┘
```

| Boundary | AuthN/AuthZ | Validation | Arbitrary renderer → privileged? |
|----------|-------------|------------|----------------------------------|
| Renderer → Preload | None (any page JS) | Method allowlist only | Yes — only listed APIs |
| Preload → IPC | Channel allowlist | Per-handler (uneven) | Yes — only registered channels |
| Renderer → HTTP API | Bearer JWT (most routes) | Route validators | Yes if JWT in `localStorage` stolen |
| IPC destructive ops | Master PIN (some) | PIN + phrase (init) | Partially — several mutators lack auth |

**Single main BrowserWindow** loads Express-served static frontend. Optional KDS `BrowserWindow` via IPC. Popup windows via `setWindowOpenHandler`. **No `BrowserView`. No `webviewTag`.**

## 8. XSS → RCE attack analysis

Assume attacker-controlled JavaScript in the renderer (XSS, compromised static asset, malicious inline script under CSP `'unsafe-inline'`).

| # | Capability | Reachable? | Mechanism |
|---|------------|------------|-----------|
| 1 | Execute JavaScript | **Yes** | XSS / inline scripts |
| 2 | Access Node | **No** | `nodeIntegration: false` + contextIsolation |
| 3 | Access preload APIs | **Yes** | `window.electronAPI` |
| 4 | Invoke privileged IPC | **Yes** | Allowlisted methods; several **unauthenticated** |
| 5 | Access SQLite | **Indirect** | IPC restore/fixes/init; HTTP API with stolen JWT |
| 6 | Access JWT **signing** secret | **No** | Not in IPC/settings; safeStorage |
| 7 | Execute OS commands | **No direct**; print via API | thermal `execFile` needs authenticated HTTP |
| 8 | Access filesystem | **Limited** | Backup/restore with Master PIN; arbitrary restore path if PIN known |
| 9 | Invoke printers | **Yes** | HTTP + JWT; IPC `save-printer` unauthenticated |
| 10 | Modify POS data | **Yes** | Stolen `localStorage.token` → full API as logged-in role |

**Realistic chain (HIGH business impact, not classic Node RCE):**

1. XSS in renderer (CSP allows `'unsafe-inline'`).
2. Read `localStorage.token` → call `/api/*` as owner/cashier.
3. Optionally call unauthenticated IPC (`db-apply-safe-fixes`, `save-printer`, `get-daily-summary`, `restart-and-install`).
4. Outcome: financial fraud, schema mutation, forced update restart — **without** reading JWT signing secret or spawning a shell.

**Enabling `sandbox: true` (Phase A) reduces Chromium process-isolation risk but does not close this chain.** Phase B IPC auth + CSP tightening are still required.
